# F01: конфигурация и безопасный просмотр

## Изменения

- Общая структурная валидация в pipeline_config.py.
- pipeline.py читает --config; значение по умолчанию сохраняется: config.yaml.
- Относительные source_dir/obsidian_dir считаются от каталога конфига.
- Источник должен существовать; выходной каталог может отсутствовать.
- Выходной путь и его предки не должны быть заняты обычным файлом.
- Плохой YAML, неверная структура состояния и неположительный --limit
  отклоняются до операций над аудио и выходными каталогами.
- --list, --dry-run и отсутствие кандидатов не загружают Whisper,
  не вызывают Ollama/FFmpeg и не создают выходных каталогов.
- Зависимости обработки импортируются только в нужном сценарии.
- scripts/check.py использует ту же валидацию без проверки реальных путей.

## Границы

Обновлён основной pipeline.py. Перенос остальных служебных CLI на общий
конфиг остаётся отдельным шагом. Не исправлялись коллизии имён, транзакционность,
ссылки Obsidian, качество ASR и обработка ошибок отдельных аудиофайлов.
Рабочий config.yaml сохраняется.

## Приёмка

Запуск CLI в изолированном временном каталоге: валидные previews,
несуществующий источник, плохой YAML/типы, повреждённое состояние,
выходной путь-файл, относительный конфиг из другой рабочей папки.
Сравнить имена, байты и mtime входа/выхода до и после каждого preview.
Подменить тяжёлые зависимости запретом импорта для подтверждения отсутствия
инициализации моделей. Обычный путь проверить отдельно синтетическим WAV
и подставным ASR, не пользовательским аудио.

## Результат проверки — 2026-09-15

28 CLI-сценариев прошли в Ubuntu с Python 3.10.12:
просмотр нового/существующего вывода, config.yaml по умолчанию, относительные
пути из другого cwd, пустая выборка, фильтр, нулевой/отрицательный limit,
ошибочный YAML и тип корня, отсутствие обязательного поля/источника,
неверные расширения, частота, каналы, VAD, device, compute_type, нулевой символ
в пути, неверный ai/enabled, файл вместо каталога вывода, три формы плохого
состояния, обычная обработка и повторный запуск уже обработанного файла.

Preview проверялся запретом импорта faster_whisper, requests, tqdm и slugify;
файловые снимки сравнивали имена, содержимое и mtime. Python запускался с -B,
чтобы исключить служебный bytecode cache из измерения.
Обычный путь использовал синтетический WAV, настоящий FFmpeg и подставной ASR:
создана заметка, состояние ok, хеш переименованного оригинала сохранён.
Реальные модели и личные аудио не использовались.

Проверка выполнена одноразовым внешним сценарием; постоянный набор
регрессионных тестов ещё не внедрён. GitHub CI пока проверяет только структуру.
