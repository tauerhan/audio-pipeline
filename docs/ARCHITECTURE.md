# Архитектура

## Текущее устройство

`pipeline.py` объединяет обнаружение файлов, FFmpeg, Whisper, запрос Ollama,
переименование, Markdown, CSV и JSON. `summarize_notes.py` отдельно читает заметки,
обращается к Ollama и обновляет summary. Четыре остальных скрипта обслуживают
названия и повторное распознавание; часть логики дублируется.

После F01 основной pipeline и scripts/check.py используют pipeline_config.py
для общей структурной валидации; основной CLI дополнительно проверяет пути.

Преобразование по умолчанию только приводит аудио к моно 16 кГц; дополнительный FFmpeg-фильтр задаётся явно через `convert.audio_filter`. Текущий ASR-профиль: large-v3 / ru / CPU float32 / без VAD / без фиксированного prompt. Словарные hotwords можно задать в `transcription.hotwords`.

Состояние обработки хранится в каталоге вывода, а не в кодовом репозитории.
Ключ быстрого поиска включает путь, размер и mtime; дополнительно используется SHA-256.
Временные WAV попадают в `processed_audio/`, заметки — в `transcripts/`.
`processed_audio/` сейчас не является архивом исходных MP3/M4A.

## Целевой поток

```mermaid
flowchart LR
  A[Входящие аудио] --> B[Проверка и SHA-256]
  B --> C[FFmpeg]
  C --> D[Локальное русское ASR]
  D --> E[Локальная Ollama: заголовок и summary]
  E --> F[План имени и проверка коллизий]
  F --> G[Архив оригиналов]
  G --> H[Заметка Obsidian со ссылкой]
  H --> I[Согласованное состояние и индекс]
```

Это цель, а не описание уже реализованного транзакционного поведения.

## Постепенное разделение

После фиксации поведения проверками выделять по одному компоненту:

```text
src/audio_pipeline/
  config.py        # загрузка и валидация настроек
  discovery.py     # поиск и идентичность файлов
  audio.py         # адаптер FFmpeg
  asr.py           # адаптер faster-whisper
  summarization.py # адаптер Ollama и схема результата
  naming.py        # имена, коллизии и пути
  obsidian.py      # frontmatter, Markdown и ссылки
  state.py         # журнал шагов и восстановление
  cli.py           # запуск сценария
tests/
  unit/
  integration/
```

Эти каталоги ещё не созданы: пустые модули не дают работающей архитектуры.
Корневые команды при миграции остаются совместимыми обёртками.
Сначала конфигурация и безопасный план операций, затем хранение и адаптеры.

## Решения первого этапа

- GitHub хранит разработку; личный аудиоархив и Obsidian остаются вне Git.
- Ubuntu остаётся средой выполнения. Windows-копия служит для просмотра подготовки.
- Не переносить рабочие данные при добавлении Git.
- CI не требует GPU, весов, SSH в Ubuntu или доступа к Obsidian.
- SQLite, web UI, очередь задач и RAG отложены до надёжного одиночного сценария.
- Отдельный каталог архива должен быть исключён из входного сканирования.
- Перенос между файловыми системами требует копирования, проверки хеша и
  удаления источника только после подтверждённого сохранения; обычный rename
  этого сценария не обеспечивает.
