# Audio Pipeline

Локальная обработка русскоязычных аудиозаписей: FFmpeg → faster-whisper →
Markdown для Obsidian → заголовок и краткое содержание через Ollama.

Проект развивается из шести рабочих Python-скриптов. Цель следующего этапа:
надёжно получать заметку с работающей ссылкой на аудио и переносить переименованный
файл в отдельный архив без потери данных и повторной обработки.

## Что есть сейчас

- Поиск аудио, конвертация в WAV, русская транскрипция и таймкоды.
- Профиль ASR по умолчанию: Whisper large-v3, CPU/float32, без VAD и фиксированного prompt; фильтр аудио отключён, hotwords задаются настройкой.
- YAML frontmatter, Markdown, индекс CSV и состояние JSON.
- Необязательная генерация заголовков, тегов и summary через локальную Ollama.
- Переименование исходников и вспомогательные скрипты восстановления.

**Ограничения:** основной pipeline переименовывает аудио в исходной папке;
отдельный каталог готовых оригиналов ещё не реализован. Путь к файлу в заметке
пока записывается как текст, а не как кликабельная ссылка. AI по умолчанию выключен.
Аудит и приоритеты: [docs/AUDIT.md](docs/AUDIT.md).

## Структура

```text
audio-pipeline/
├── pipeline.py                 # текущая точка входа: аудио → заметка
├── pipeline_config.py          # ранняя валидация настроек и путей
├── summarize_notes.py          # повторная генерация summary
├── retry_bad_audio.py          # повторное распознавание
├── fix_bad_titles.py            # обслуживание названий
├── rename_processed_sources.py # старый скрипт с жёстким путём
├── rename_sources_by_hash.py    # восстановление соответствий по хешу
├── config.example.yaml         # публичный пример настроек
├── requirements*.txt           # зависимости приложения и проверки
├── scripts/check.py            # лёгкая проверка репозитория
├── docs/                       # архитектура, аудит, работа с Codex
├── docs/plans/                 # планы небольших этапов
├── evals/                      # протокол оценки качества русского ASR
├── .github/                    # CI и шаблоны Issues/PR
├── AGENTS.md                   # правила для coding-агента
├── PROGRESS.md                 # состояние и следующий шаг
└── feature_list.json           # задачи и критерии проверки
```

Скрипты оставлены в корне, чтобы сохранить существующий запуск из Ubuntu.
План перехода к пакету `src/audio_pipeline/`: [архитектура](docs/ARCHITECTURE.md).
`config.yaml`, `venv/`, `data/`, аудио, заметки и модели не входят в Git.

## Установка в Ubuntu

Проверенная исходная среда: Python 3.10.12. Требуется Python 3.10+ и FFmpeg.
Версии прямых зависимостей зафиксированы по окружению проекта; это ещё не полный
lock-файл и не доказательство воспроизводимости чистой установки.

```bash
sudo apt install python3-venv ffmpeg
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp -n config.example.yaml config.yaml
```

Запускайте команды из корня проекта. В существующей установке сохраните
свой `config.yaml` и `venv/`; не переустанавливайте их ради Git.
В новом конфиге укажите реальные папки источников и Obsidian.
Пробелы внутри YAML-кавычек не нужно экранировать обратной косой чертой.

Для первого запуска используйте копии аудио в отдельной папке.
Обычный запуск переименовывает исходники. `--list` и `--dry-run`
не меняют входные файлы и выходные каталоги и не загружают модели.
Конфигурация проверяется до обработки; отсутствующий source_dir даёт ошибку.
Можно передать `--config /path/to/config.yaml`. Относительные пути источника
и Obsidian считаются от папки конфига, а не от текущего рабочего каталога.
Первая загрузка Whisper может скачивать веса; затем распознавание выполняется
локально. Для полностью автономной работы подготовьте веса заранее.
Ollama устанавливается отдельно; её HTTP endpoint должен быть локальным.
OpenAI API приложению не требуется: Codex используется для разработки.

```bash
python pipeline.py --help
python pipeline.py --list
python pipeline.py --dry-run --limit 1
python pipeline.py --limit 1
```

После настройки Ollama:
```bash
python summarize_notes.py --list
python summarize_notes.py --limit 1
```

Перед массовыми операциями обслуживания прочитайте [аудит](docs/AUDIT.md).
`rename_processed_sources.py` содержит старый абсолютный путь и не является
универсальной командой для нового хранилища.

Обзор моделей русского ASR и порядок сравнения: [docs/MODELS_RU.md](docs/MODELS_RU.md).

## Проверка без моделей

```bash
python -m pip install -r requirements-check.txt
python scripts/check.py
```

В Ubuntu альтернативно: `make check PYTHON=venv/bin/python`.
Проверяются синтаксис Python, YAML/JSON, структура задач и исключение локальных
данных из Git. Это **не** проверка качества распознавания, интеграционный тест,
линтер или доказательство безопасного переименования.
Поведенческие тесты пока отсутствуют; их внедрение выделено отдельной задачей.
